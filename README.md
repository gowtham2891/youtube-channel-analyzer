**▶ Try it live — [gowtham2891-yt-analyzer.streamlit.app](https://gowtham2891-yt-analyzer.streamlit.app)** · runs in mock mode, no credentials needed.

Point it at a YouTube channel. It fetches the uploads and transcripts, computes
what actually happened, and uses **Gemini only for the qualitative read** —
themes, hook patterns, gaps, and what to make next.

The split is deliberate: **every number in the report is computed in Python, not
generated by a model.** LLMs are unreliable at arithmetic and very convincing
when wrong, so they never touch the statistics.

## Pipeline

```
  @channel  ·  youtube.com/…  ·  UC…
        │
        ▼
┌──────────────────┐  Resolves handles, URLs, legacy /user/ and /c/ paths,
│  Resolve channel │  falling back to search when forHandle misses
└────────┬─────────┘
         ▼
┌──────────────────┐  Walks the uploads playlist, batches videos.list 50 at
│  Fetch uploads   │  a time (the API's hard cap)
└────────┬─────────┘
         ▼
┌──────────────────┐  Median · engagement · cadence · consistency · outliers
│  Compute stats   │  · weekday performance · duration buckets · tag frequency
└────────┬─────────┘                        ← pure Python, fully tested
         ▼
┌──────────────────┐  Reads the most-viewed videos' transcripts; missing
│  Read transcripts│  captions degrade, never abort
└────────┬─────────┘
         ▼
┌──────────────────┐  Titles + tags + transcript hooks → themes, patterns,
│  Gemini analysis │  opportunities, recommended topics
└──────────────────┘
```

## What it computes

| Metric | Why it's there |
| --- | --- |
| **Median** views (not just mean) | One viral video makes a mean useless. The median is what a typical upload does. |
| **Outliers** (>2× median) | Measured against the median, so a viral hit can't hide the *other* overperformers. |
| **Consistency score** (0–100) | Coefficient of variation on upload gaps. 100 = perfectly even spacing. |
| **Upload cadence** | Counts *intervals*, not videos — n uploads span n−1 gaps, so dividing by video count overstates the rate by n/(n−1). |
| **Weekday performance** | Ranked by **mean views per day**, not upload count. Posting most often on Monday says nothing about whether Monday works. |
| **Duration buckets** | Mean views per length band — does long-form actually outperform Shorts on *this* channel? |
| **Engagement rate** | (likes + comments) / views, per video and averaged. |

## Getting API keys

**YouTube Data API v3** — free, 10,000 quota units/day:
1. Create a project at [console.cloud.google.com](https://console.cloud.google.com)
2. Enable **YouTube Data API v3**
3. Create an API key → `YOUTUBE_API_KEY`

A 50-video analysis costs roughly 5 units, so the free tier is generous.

**Gemini** — free tier at [aistudio.google.com](https://aistudio.google.com) → `GEMINI_API_KEY`

**Transcripts** need no key: `pip install -e ".[transcripts]"`

## Mock mode

`DATA_SOURCE=mock` generates a deterministic synthetic channel of 50 videos with
uneven view counts, two planted outliers, mixed Shorts and long-form, irregular
upload gaps, and **transcripts missing for about a third of videos** — exactly
how the real API behaves.

That realism is the point. Statistics tests run against data with genuine
variance and genuine gaps, so they catch things a uniform fixture never would
(the cadence estimator bug above was found this way).

## Configuration

| Variable | Purpose | Default |
| --- | --- | --- |
| `DATA_SOURCE` | `mock` or `youtube` | `mock` |
| `ANALYZER` | `mock` or `gemini` | `mock` |
| `YOUTUBE_API_KEY` | Data API v3 key | — |
| `GEMINI_API_KEY` / `GEMINI_MODEL` | Gemini credentials | `gemini-2.0-flash` |
| `MAX_VIDEOS` | Uploads to fetch | `50` |
| `MAX_TRANSCRIPTS` | Transcripts to read (most-viewed first) | `10` |
| `TRANSCRIPT_LANGUAGES` | Preference order | `en,te,hi` |
| `FETCH_TRANSCRIPTS` | Read transcripts at all | `true` |
| `MAX_RETRIES` | Retries on transient API errors | `3` |

## Design notes

**Numbers and narrative are separated.** `analytics.py` is pure Python with no
provider dependency, and it runs *before* the LLM stage. If Gemini fails, times
out, or isn't configured, the pipeline logs it and returns the full quantitative
report anyway — tested explicitly.

**Failure is expected, not exceptional.** Missing captions are the norm
(disabled, music, age-restricted), so `fetch_transcript` returns a `Transcript`
with `error` set rather than raising. A 403 from the Data API is translated into
a message naming the three actual causes: bad key, API not enabled, quota gone.

**Hidden statistics are handled.** Uploaders can hide like counts; the API then
omits the field entirely rather than sending zero. Every parse defaults safely.

**Charts follow one rule set.** Single-series, single-hue, no dual-axis anywhere
— views and upload counts get separate charts rather than a shared distorted
scale. Every chart ships with a table view beside it.

## Deploy your own

Ready for [Streamlit Community Cloud](https://share.streamlit.io): free, and it
redeploys on every push to `main`.

1. Sign in at [share.streamlit.io](https://share.streamlit.io) with GitHub.
2. **Create app** → this repo, branch `main`, main file `app.py`.
3. Under **Advanced settings**, choose Python **3.11**.
4. Set the custom subdomain to `gowtham2891-yt-analyzer` so it matches the link above.
5. Deploy — the first build takes a couple of minutes.

No secrets are needed for the demo. To switch it to the live providers, open
**Settings → Secrets** in the Streamlit dashboard and paste:

```toml
DATA_SOURCE = "youtube"
ANALYZER = "gemini"
YOUTUBE_API_KEY = "your-youtube-key"
GEMINI_API_KEY = "your-gemini-key"
```

`app.py` copies those secrets into the environment before settings are resolved,
so the exact same configuration works locally through `.env` and in the cloud
through the dashboard — no code changes either way.
